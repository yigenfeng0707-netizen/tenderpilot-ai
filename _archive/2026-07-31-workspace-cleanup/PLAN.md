# AI+∞ 开发者创作大赛交付计划

## 目标与边界

交付 `TenderPilot AI`：面向运营团队的投标与项目申报智能协作台。它将长文档中的要求转换为可追溯的需求清单、证据矩阵、风险任务和受约束的内容草稿，降低运营在材料准备、跨部门协作和合规检查中的重复劳动。

该项目应是活动期间首次发布的原创作品，且在 2026-08-10 23:59 前完成下列公开交付：

1. 魔搭创空间可访问、可运行的 Demo。
2. 提交至赛事门户的作品记录。
3. 与作品强相关的研习社原创创作手记。
4. 与 Demo、文章和赛事表单一致的项目说明与链接。

比赛页面未明确时区，计划按北京时间（UTC+8）执行；提交前必须再次在官方页面确认时区和作品表单字段。

## 产品范围

### 必做 MVP

1. 文档/文本输入：粘贴招标或申报要求；如实现文件上传，必须限制类型和大小并清楚说明解析范围。
2. 要求拆解：把原文拆为编号要求、截止项、交付物、评分项和待确认项，并附原文位置或引用片段。
3. 证据矩阵：把每个要求映射到已有材料、缺失证据、负责人、状态和风险级别。
4. 风险与任务：根据缺失、截止和不确定性生成可编辑任务清单，支持状态更新。
5. 受约束内容草稿：只从用户提供的事实和证据生成草稿；每段显示来源要求/证据，禁止把推断包装成已证实事实。
6. 可复现演示：内置脱敏样例，用户无需 API key 即可完整体验核心流程。
7. 明确限制：非法律/招投标意见；AI 输出需要人工审核；Demo 样例不代表真实投标材料。

### 不做

1. 不接入真实招投标平台或自动提交投标文件。
2. 不处理或上传真实敏感投标资料到未审查的第三方服务。
3. 不声称模型、数据或效果未经验证的能力。
4. 不为追求范围而实现与运营提效无关的泛用聊天机器人。

## 自动化执行阶段

### P0：规则与表单冻结

1. 已确认报名状态为“已报名”，作品提交页显示当前投稿数为 0。
2. 重新进入已登录作品提交页，点击“新建作品”，逐字段记录标题、简介、分类、封面、Demo、文章、代码、视频、标签、协议和确认项。已核验的实际字段为：作品名称、作品简介、魔搭创空间 URL、研习社创作手记 URL，以及额外内容激励“是/否”。
3. 将字段、字数限制、支持格式、保存/更新规则和最终提交按钮写入 `docs/portal-requirements.md`。
4. 如果官方公告或表单与本计划冲突，以最新官方内容更新计划和 TODO 后再继续。

验收：所有门户字段都有对应交付物；没有根据猜测填写字段。

### P1：项目基线与可复现 Demo

1. 初始化项目、依赖锁定、环境变量示例、开发与生产运行命令。
2. 实现本地固定样例和端到端主流程，确保没有 API key 时仍可演示。
3. 如使用模型 API，加入超时、失败回退、输入脱敏提醒、输出引用和显式演示模式。
4. 为核心解析、矩阵生成、风险排序和引用约束建立测试。
5. 为桌面和移动端运行浏览器冒烟测试，生成截图。

验收：全新环境能按 README 启动；样例从输入到结果无阻断；测试和构建均通过。

### P2：评分导向的内容与质量

1. 撰写真实运营痛点、用户画像、现状成本、成功指标和推广路径。
2. 形成 3 至 5 分钟演示脚本：问题、输入、要求拆解、证据矩阵、风险任务、草稿与人工审核。
3. 准备项目封面、演示截图和短视频；内容只展示真实可运行功能。
4. 撰写研习社创作手记，含原创性、技术架构、可复现步骤、失败/限制、未来迭代和 Demo 链接。
5. 维护依赖、模型、数据、图片和文案来源与许可证清单。

验收：所有对外描述可由代码、Demo 或来源文件证明；没有夸大效果、虚构用户或虚假数据。

### P3：部署与公开资产核验

1. 部署到魔搭创空间，设置赛期为“仅公开体验”或官方允许的等效可访问状态。
2. 用未登录浏览器验证 Demo URL、首页、样例流程和错误状态。
3. 发布研习社文章，使用实际可访问的 Demo URL，且项目名称、功能和截图完全一致。
4. 发布与作品强相关的小红书参赛心得，只使用真实体验、真实截图和正确话题/官方账号要求；不自动发布或刷互动。
5. 建立赛期巡检：每日检查公开 URL、主流程、文章 URL 和浏览器控制台错误，直到评审结束。

验收：每个外部 URL 可公开访问；外部文案与本地 README 和赛事表单完全一致。

### P4：门户保存、最终提交与持久化验证

1. 预填作品表单草稿，逐项运行 URL、字数、必填项和一致性检查。
2. 展示最终字段快照与提交影响，获得用户对“提交/更新作品”的明确确认。
3. 确认后提交，等待成功提示。
4. 刷新页面，验证作品数量、标题、全部 URL、标签、正文格式、状态和版本/更新时间。
5. 在 `docs/delivery-notes.md` 记录非敏感证据：赛事页 URL、提交页 URL、状态、提交时间、公开资产 URL 与截止时区。

验收：门户成功状态和刷新后数据完全一致。仅代表已提交，不宣称获奖、通过评审或被接受。

## 自动化边界

可自动执行：本地开发、测试、构建、文档生成、链接检查、截图、部署前验证、表单草稿校验、赛期巡检和提交后刷新核验。

需要用户明确确认：登录新账号、使用付费资源、公开发布到创空间/研习社/小红书、同意平台条款、最终赛事作品提交或覆盖已有提交。自动化不得绕过验证码、平台访问控制、人工审核或反刷量机制。

## 风险与停止条件

1. 赛事表单字段或公告存在变化：停止填写，更新 `docs/portal-requirements.md` 和 TODO。
2. Demo 无法公开访问或核心流程失败：停止提交，先修复并重新验证。
3. 任何资产无法证明原创性、许可证或真实性：停止公开发布，替换或补充证据。
4. 需要输入真实敏感材料：停止，改用脱敏样例并要求用户决定数据处理方式。
5. 进入最终“提交作品”动作：停止等待用户明确确认。
