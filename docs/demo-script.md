# TenderPilot AI 演示录屏脚本

建议时长：2 分 30 秒至 3 分 30 秒。仅录制当前实现的真实功能。

## 0:00-0:20 问题

画面：产品首页与“运营材料，从读不完到可协作”标题。

旁白：

> 运营团队准备投标或项目申报材料时，常常要在一份长通知中找截止时间、案例、预算和评分项，再逐个问同事要证明。TenderPilot AI 想先把这些要求变成一张可协作的行动图。

## 0:20-0:45 输入与数据边界

画面：点击“加载脱敏样例”，展示输入框和演示模式提示。

旁白：

> 这个 Demo 使用脱敏的内置样例，默认不需要 API Key，文本仅在当前浏览器处理。真实使用时不应粘贴未脱敏的投标、客户或个人敏感资料。

## 0:45-1:25 要求拆解

画面：点击“拆解要求”，滚动展示要求清单。

旁白：

> 一次拆解后，系统将截止节点、资质与案例、方案交付、预算报价和评分项分别列出。每一项都有原文引用和优先级，所以团队能先看到最容易遗漏、最影响交付的内容。

## 1:25-1:55 证据矩阵与任务

画面：展示证据矩阵，切换一项状态；继续展示风险任务并勾选一项。

旁白：

> 接下来，每项要求都有当前证据、负责人和状态。缺少案例证明、负责人资质或报价盖章时，团队不会只看到一段文字，而是直接得到可跟进的风险任务。

## 1:55-2:35 受约束草稿与人工审核

画面：展示草稿区、引用依据和限制说明，点击“复制草稿”。

旁白：

> 最后的草稿只引用输入中已经抽取的要求。没有证据的内容会被保留为待确认，而不是被包装成事实。它不是投标、法律、财务或合规意见，最终材料仍必须由负责人审核。

## 2:35-2:55 总结

画面：回到产品标题或展示“为什么不是普通聊天框”。

旁白：

> TenderPilot AI 的重点不是替人做最终承诺，而是先让证据、缺口和协作关系变得可见，帮助运营团队更稳地完成材料准备。

## 录制检查

1. 使用内置样例，不展示真实项目文件、个人信息、账号、浏览器标签或赛事凭据。
2. 录制前在桌面和移动端各跑一次完整主流程。
3. 不展示未实现的上传、模型调用、多人实时协作、线上数据存储或自动提交能力。
4. 发布视频前，将标题、功能说明、截图和 Demo 链接与 README、研习社文章及赛事表单逐项对齐。
