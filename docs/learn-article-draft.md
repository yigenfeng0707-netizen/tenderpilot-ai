# 从一份申报通知到一张协作图：我做了 TenderPilot AI

> 发布前须替换本段：Demo 链接为实际魔搭创空间 URL，并在研习社编辑器中核验标题、截图和链接。不要在尚未部署时发布本文。

## 为什么做它

做运营方案、项目申报或投标材料时，最耗时间的往往不是写第一版，而是反复找要求、问材料、核对证明和确认谁负责。通知里的一句“附案例证明”可能被漏掉，团队写出的内容也可能先于事实核验。

我想做的不是一个泛用聊天框，而是让运营人员能把材料要求变成一张可协作、可追溯的行动图。

## TenderPilot AI 做了什么

Demo 以一段脱敏的项目要求为输入，完成四个步骤：

1. 拆解截止节点、资质与案例、方案交付、预算与报价、评分项。
2. 每一条要求保留输入原文，形成证据矩阵，展示当前缺口、负责人和状态。
3. 把缺口转换成带优先级的风险任务。
4. 生成带引用依据的内容草稿。没有提供证据的内容会保留为待确认项，而不是被写成已证实事实。

在线体验：将在部署完成后补充实际魔搭创空间 URL。

## 我刻意保留的边界

这个版本默认离线运行，输入文本只留在当前浏览器中，不需要 API Key，也不会上传真实资料。它不是投标、法律、财务或合规意见。真实项目中，负责人仍应核验资格、预算、材料和最终承诺。

## 技术实现

为了让任何人都能复现，Demo 使用浏览器原生交互和 Node.js 内置模块：

- 规则驱动的中文文本分类，不依赖外部模型服务。
- 内置脱敏样例，零配置即可演示完整路径。
- 对每条输出保留原文位置，草稿只引用已抽取的要求。
- 使用 Node 内置测试覆盖要求抽取、任务生成和草稿来源约束。

## 如何体验

1. 打开 Demo。
2. 点击“加载脱敏样例”。
3. 点击“拆解要求”。
4. 在证据矩阵中调整状态，查看风险任务和引用草稿。
