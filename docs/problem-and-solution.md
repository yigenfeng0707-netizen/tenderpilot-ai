# TenderPilot AI：运营材料协作的证据优先工作流

## 目标用户

- 负责投标、项目申报、活动运营方案的运营人员。
- 需要为多项材料分派负责人、追踪证据与核对截止节点的项目经理。
- 需要在提交前减少遗漏和未经核验承诺的协作团队。

## 真实问题

一份项目通知通常混合了截止时间、资质、案例、预算、评分项和方案内容。运营人员需要在多份文档和多人之间来回确认，常见结果是：

1. 截止节点和硬性材料被埋在长文本中。
2. 团队不知道每项要求需要什么证据、谁负责、当前是否可交付。
3. 内容草稿先于事实核验，导致“看起来完整”却缺少证明的风险。

## 方案

TenderPilot AI 将已脱敏文本转为一个可见的协作面：

1. **要求拆解**：按截止节点、资质与案例、方案交付、预算与报价、评分项分类，并保留原文。
2. **证据矩阵**：每项要求都有当前证据、负责人和可更新状态，先展示缺口。
3. **风险任务**：把每项待补证据转成任务，并按高、中、低优先级排序。
4. **受约束草稿**：只使用输入文本列出的依据；没有证据的事实明确保留为待补充，而不是自动承诺。

## 成功指标

- 在一次演示中，用户可以从一段要求文本得到不少于 5 条可追溯要求。
- 每条要求均具备原文引用、优先级、负责人、证据状态和对应任务。
- 草稿含引用依据与人工审核声明，不把输入中不存在的信息描述为已确认事实。
- 任何用户无需 API Key 就能在本地完成以上流程。

## 推广路径

先服务需要频繁整理材料的活动运营、品牌合作和项目申报团队，再扩展为内部知识库、任务系统和企业权限体系的前置材料治理层。Demo 保持离线，以便团队先在不上传敏感文件的条件下体验流程。

## 边界

当前版本是规则驱动、浏览器本地运行的演示原型，不替代招投标、法律、财务或合规判断。真实生产环境必须有数据脱敏、访问控制、审计、材料版本管理和人工复核。
